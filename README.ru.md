# MR Navigator for GitLab

[![Build](https://github.com/MrKamenAdmin/mr-navigator/actions/workflows/build.yml/badge.svg)](https://github.com/MrKamenAdmin/mr-navigator/actions/workflows/build.yml)

[English](README.md) · **Русский**

Плагин для GoLand, чтобы ревьюить merge request'ы GitLab прямо в IDE: с работающими переходами по коду в diff и без сгенерированного мусора вроде `*.pb.go`.

Встроенная интеграция с GitLab показывает diff MR из ревизий, поэтому Ctrl+клик, Find Usages и остальная навигация там не работают, а сгенерированные файлы заслоняют настоящие изменения. Этот плагин выкачивает MR и ставит справа в diff настоящий файл проекта, скрывает сгенерированные файлы и держит всё ревью — комментарии, suggestions, approve — в одном месте.

## Возможности

- **Список MR** проекта: все открытые, ждут моего ревью, назначены на меня, мои, смёрженные; поиск по названию.
- **Checkout в один клик.** Плагин скачивает MR, прячет ваши незакоммиченные изменения в stash и переключается на локальную ветку `mr/<номер>`. Кнопка **«Вернуться»** возвращает на вашу ветку и достаёт изменения из stash.
- **Diff с переходами.** Справа в diff настоящий файл проекта, поэтому работают Ctrl+клик, Find Usages и остальная навигация, в том числе по символам за пределами изменённых строк. «Следующий/предыдущий файл» листает весь MR.
- **Скрытие сгенерированных файлов.** Файлы с заданными вами суффиксами (например `.pb.go`) не попадают ни в дерево файлов, ни в diff. Папки, где кроме таких файлов ничего нет, тоже пропадают, на любой глубине. **«Показать скрытые (N)»** временно возвращает их. По умолчанию скрытие выключено — см. [Настройки](#настройки).
- **Комментарии:**
  - иконки тредов на полях diff; клик открывает тред: прочитать, ответить, сделать Resolve, открыть в браузере;
  - **+** на строке под курсором или правый клик → **«Комментарий к строке / выделению (GitLab MR)»** — новый тред;
  - **многострочные комментарии**: выделите строки и нажмите **+**. В unified-режиме диапазон может начинаться на удалённой строке и заканчиваться на добавленной, как в GitLab;
  - **suggestions**: **«Предложить изменение»** вставляет блок `suggestion` с текущим кодом строки или строк, автор MR применяет его в GitLab;
  - вкладка **«Обсуждение»** — все треды, открытые первыми; двойной клик по треду к строке открывает diff прямо на этой строке.
- **Вкладка «Файлы»:** +/− строк у каждого файла, отметки «просмотрен» (ставятся при открытии файла, Пробел переключает, новые коммиты сбрасывают).
- **Несколько репозиториев в одной папке:** если в открытой папке несколько репозиториев GitLab, появляется переключатель репозитория.
- **Approve и отзыв approve**, описание MR, открытие в браузере.
- **Self-hosted GitLab** и gitlab.com, REST API v4. Настройки прокси и сертификатов IDE применяются.

## Требования

- GoLand 2026.2 или новее. Плагин использует только IntelliJ Platform, поэтому должен работать и в других IDE на её основе версии 2026.2+, но проверен только в GoLand.
- `git` в `PATH` (или путь к нему в настройках плагина).
- Personal access token GitLab со scope `api`.

## Установка

Плагина пока нет в JetBrains Marketplace, собирается из исходников.

Для запуска Gradle нужен JDK 17+; JDK 25, который требует IntelliJ Platform 2026.2, скачается автоматически.

```bash
git clone https://github.com/MrKamenAdmin/mr-navigator.git
cd mr-navigator
./gradlew buildPlugin
```

Затем в GoLand: **Settings → Plugins → ⚙ → Install Plugin from Disk…** и выберите `build/distributions/mr-navigator-<версия>.zip`.

Попробовать в отдельной тестовой IDE, не трогая свою GoLand:

```bash
./gradlew runIde
```

Если Gradle не находит GoLand `2026.2`, впишите в `gradle.properties` точную версию из **Help → About**, например `platformVersion = 2026.2.1`.

## Начало работы

1. Откройте окно **MR Navigator** (левая боковая панель).
2. В первый раз появится форма подключения:
   - адрес GitLab подставляется из git remote проекта — поправьте, если GitLab стоит на подпути;
   - **«Создать токен в GitLab →»** открывает страницу создания токена с уже заполненными именем и scope `api`;
   - вставьте токен и нажмите **«Подключить»**. Токен хранится в хранилище паролей IDE.
3. Выберите MR и нажмите **«Checkout и ревью»**. Откроется diff первого файла, а карточка покажет, что рабочая копия на коде MR.
4. При желании настройте скрытие сгенерированных файлов в [Настройках](#настройки).
5. Ревьюйте: листайте файлы, переходите по коду, комментируйте через **+**, выделяйте строки для многострочного комментария, предлагайте изменения.
6. **Approve**, затем **«Вернуться»** — и вы на своей ветке с восстановленными изменениями.

Без checkout diff тоже откроется, но справа будет ревизия, а не файл проекта, и переходы работать не будут — об этом пишет заголовок diff.

## Настройки

**Settings → Tools → MR Navigator:**

- адрес и токен GitLab;
- **скрытие файлов**: перечислите суффиксы по одному в строке (например `.pb.go`, `.pb.gw.go`, `_mock.go`) и включите **«Скрывать файлы с этими суффиксами…»**. По умолчанию список пуст, а скрытие выключено;
- путь к `git`, авто-stash при checkout.

## Как устроено

| Исходник (`src/main/kotlin/me/brekhin/mrnavigator/`) | Что делает |
|---|---|
| `api/GitLabClient.kt`, `api/Models.kt` | GitLab REST API v4 (`/merge_requests`, `/diffs`, `/discussions`, approvals) через `HttpRequests` IDE |
| `git/GitCli.kt`, `git/RepoScanner.kt` | git из командной строки: fetch `refs/merge-requests/<iid>/head`, stash, checkout, `git show`; поиск репозиториев в папке проекта. API плагина Git4Idea не используется: он внутренний и с 2025.3 разбит на модули |
| `core/DiffLineMap.kt` | соответствие строк старой и новой версии по hunk'ам; позиции комментариев и `line_range` / `line_code` для многострочных, с подсчётом строк как в `lib/gitlab/diff/parser.rb` GitLab |
| `core/HiddenFiles.kt`, `ui/ChangesTree.kt` | скрытие файлов; папки строятся только из показанных файлов, поэтому папки из одних скрытых файлов не появляются |
| `diff/MrDiffOpener.kt` | цепочка diff'ов: слева base-ревизия, справа локальный файл |
| `diff/MrDiffExtension.kt`, `diff/CommentMarkers.kt` | иконки тредов, **+**, диапазоны и suggestions в side-by-side, unified и односторонних diff |
| `core/MrReviewService.kt` | состояние проекта: репозитории, загруженный MR, checkout и возврат, отметки «просмотрен» |
| `ui/*` | окно, форма подключения, карточка MR, попапы тредов |

## Ограничения

- Треды, устаревшие после новых коммитов, не рисуются на полях; они есть на вкладке «Обсуждение» с пометкой «устарел».
- Для файлов, diff которых GitLab не отдаёт из-за размера, комментарии к строкам недоступны.
- Suggestions можно оставлять только на строки новой версии, как и в GitLab. Применять suggestions из IDE пока нельзя.
- В side-by-side режиме диапазон ограничен одной стороной; чтобы выделить удалённые и добавленные строки вместе, переключите diff в unified.
- Если вы правили файлы на ветке `mr/<номер>` и затем выкачали другой MR того же репозитория, эти правки уйдут в stash (с пометкой `mr-review` в `git stash list`), но «Вернуться» их не восстановит; изменения, спрятанные при первом checkout, восстановятся.

## Участие в разработке

Issues и pull request'ы приветствуются.

```bash
./gradlew test       # юнит-тесты логики, не зависящей от платформы
./gradlew runIde     # тестовая GoLand с плагином
```

С чего можно начать: английский интерфейс (вынести строки в resource bundle), применение suggestions из IDE, черновики неотправленных комментариев.
