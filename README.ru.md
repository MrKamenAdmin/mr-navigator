# MR Navigator

[![Build](https://github.com/MrKamenAdmin/mr-navigator/actions/workflows/build.yml/badge.svg)](https://github.com/MrKamenAdmin/mr-navigator/actions/workflows/build.yml)

[English](README.md) · **Русский**

Плагин для GoLand, чтобы ревьюить merge request'ы GitLab и pull request'ы GitHub и Bitbucket прямо в IDE: с работающими переходами по коду в diff и без сгенерированного мусора вроде `*.pb.go`.

Встроенные интеграции показывают diff из ревизий, поэтому Ctrl+клик, Find Usages и остальная навигация там не работают, а сгенерированные файлы заслоняют настоящие изменения. Этот плагин выкачивает MR или PR и ставит справа в diff настоящий файл проекта, скрывает сгенерированные файлы и держит всё ревью — комментарии, suggestions, approve — в одном месте.

## Возможности

- **GitLab, GitHub и Bitbucket**: gitlab.com и self-hosted GitLab (REST v4), github.com и GitHub Enterprise Server, Bitbucket Cloud и Bitbucket Data Center. Несколько подключений одновременно — каждый репозиторий работает через то, на чей сервер указывает его git remote.
- **Список MR/PR** проекта: все открытые, ждут моего ревью, назначены на меня (кроме Bitbucket), мои, смёрженные; поиск по названию.
- **Checkout в один клик.** Плагин скачивает MR/PR, прячет ваши незакоммиченные изменения в stash и переключается на локальную ветку `mr/<номер>`. Кнопка **«Вернуться»** возвращает на вашу ветку и достаёт изменения из stash.
- **Diff с переходами.** Справа в diff настоящий файл проекта, поэтому работают Ctrl+клик, Find Usages и остальная навигация, в том числе по символам за пределами изменённых строк. «Следующий/предыдущий файл» листает весь MR/PR.
- **Скрытие сгенерированных файлов.** Файлы с заданными вами суффиксами (например `.pb.go`) не попадают ни в дерево файлов, ни в diff. Папки, где кроме таких файлов ничего нет, тоже пропадают, на любой глубине. **«Показать скрытые (N)»** временно возвращает их. По умолчанию скрытие выключено — см. [Настройки](#настройки).
- **Комментарии:**
  - иконки тредов на полях diff; клик открывает тред: прочитать, ответить, сделать Resolve, открыть в браузере;
  - **+** на строке под курсором или правый клик → **«Комментарий к строке / выделению»** — новый тред;
  - **многострочные комментарии**: выделите строки и нажмите **+**. В unified-режиме диапазон может начинаться на удалённой строке и заканчиваться на добавленной;
  - **suggestions** (GitLab, GitHub): **«Предложить изменение»** вставляет блок `suggestion` с текущим кодом строки или строк; в GitLab **«Применить suggestion»** под комментарием коммитит его в ветку MR, как кнопка в вебе;
  - вкладка **«Обсуждение»** — все треды, открытые первыми; двойной клик по треду к строке открывает diff прямо на этой строке.
- **Вкладка «Файлы»:** +/− строк у каждого файла, отметки «просмотрен» (ставятся при открытии файла, Пробел переключает, новые коммиты сбрасывают).
- **Описание** отображается как GitHub-flavoured Markdown: заголовки, таблицы, чекбоксы, цитаты.
- **Несколько репозиториев в одной папке:** если в открытой папке несколько репозиториев, появляется переключатель репозитория.
- **Approve и отзыв approve**, открытие в браузере.
- Интерфейс **на русском и английском**.
- Настройки прокси и сертификатов IDE применяются.

## Требования

- GoLand 2026.2 или новее. Плагин использует только IntelliJ Platform, поэтому должен работать и в других IDE на её основе версии 2026.2+, но проверен только в GoLand.
- `git` в `PATH` (или путь к нему в настройках плагина).
- Токен для каждого хостинга:
  - GitLab: personal access token со scope `api`;
  - GitHub: classic personal access token со scope `repo`;
  - Bitbucket Cloud: API token со scope `read:user`, `read:repository`, `read:pullrequest`, `write:pullrequest` и e-mail аккаунта Atlassian либо access token репозитория, проекта или workspace;
  - Bitbucket Data Center: HTTP access token с правом Repository write.

## Установка

Плагина пока нет в JetBrains Marketplace.

**Из релиза.** Скачайте `mr-navigator-<версия>.zip` со страницы [Releases](https://github.com/MrKamenAdmin/mr-navigator/releases), затем в IDE: **Settings → Plugins → ⚙ → Install Plugin from Disk…** и выберите этот zip. Распаковывать не нужно.

**Из исходников.** Для запуска Gradle нужен JDK 17+; JDK 25, который требует IntelliJ Platform 2026.2, скачается автоматически.

```bash
git clone https://github.com/MrKamenAdmin/mr-navigator.git
cd mr-navigator
./gradlew buildPlugin
```

Затем установите `build/distributions/mr-navigator-<версия>.zip` так же.

Попробовать в отдельной тестовой IDE, не трогая свою GoLand:

```bash
./gradlew runIde
```

Если Gradle не находит GoLand `2026.2`, впишите в `gradle.properties` точную версию из **Help → About**, например `platformVersion = 2026.2.1`.

## Начало работы

1. Откройте окно **MR Navigator** (левая боковая панель).
2. В первый раз появится форма подключения:
   - хостинг и адрес подставляются из git remote проекта — поправьте, если нужно (например, GitLab стоит на подпути);
   - **«Создать токен →»** открывает страницу создания токена этого хостинга (в GitLab и GitHub — с уже заполненными именем и scope);
   - для Bitbucket Cloud укажите ещё e-mail аккаунта Atlassian;
   - вставьте токен и нажмите **«Подключить»**. Токен хранится в хранилище паролей IDE.
3. Выберите MR/PR и нажмите **«Checkout и ревью»**. Откроется diff первого файла, а карточка покажет, что рабочая копия на коде MR/PR.
4. При желании настройте скрытие сгенерированных файлов в [Настройках](#настройки).
5. Ревьюйте: листайте файлы, переходите по коду, комментируйте через **+**, выделяйте строки для многострочного комментария, предлагайте изменения.
6. **Approve**, затем **«Вернуться»** — и вы на своей ветке с восстановленными изменениями.

Без checkout diff тоже откроется, но справа будет ревизия, а не файл проекта, и переходы работать не будут — об этом пишет заголовок diff.

## Настройки

**Settings → Tools → MR Navigator:**

- **подключения**: добавить (+), удалить (−) и проверить; токен каждого хранится в хранилище паролей IDE. Сервер и токен GitLab из версии 0.2 становятся подключением автоматически;
- **скрытие файлов**: перечислите суффиксы по одному в строке (например `.pb.go`, `.pb.gw.go`, `_mock.go`) и включите **«Скрывать файлы с этими суффиксами…»**. По умолчанию список пуст, а скрытие выключено;
- путь к `git`, авто-stash при checkout;
- **язык**: автоматически (язык системы), English или русский; применяется после перезапуска IDE.

|---|---|
| `api/Hosting.kt`, `api/Http.kt`, `api/Models.kt` | типы хостингов, общий интерфейс клиента, HTTP через `HttpRequests` IDE, общая модель |
| `api/GitLabClient.kt`, `api/GitHubClient.kt`, `api/BitbucketCloudClient.kt`, `api/BitbucketServerClient.kt` | GitLab REST v4; GitHub REST и GraphQL (треды ревью); Bitbucket Cloud REST 2.0; Bitbucket Data Center REST 1.0 |
| `git/GitCli.kt`, `git/RepoScanner.kt` | git из командной строки: fetch головы MR/PR (`refs/merge-requests/<iid>/head`, `refs/pull/<n>/head`, `refs/pull-requests/<id>/from` или ветка-источник в Bitbucket Cloud), stash, checkout, `git show`; поиск репозиториев в папке проекта. | `core/DiffLineMap.kt` | соответствие строк старой и новой версии по hunk'ам; позиции комментариев и `line_range` / `line_code` для многострочных, с подсчётом строк как в `lib/gitlab/diff/parser.rb` GitLab |
| `core/UnifiedDiff.kt` | разбор сырого diff Bitbucket на файлы и hunk'и |
| `core/HiddenFiles.kt`, `ui/ChangesTree.kt` | скрытие файлов; папки строятся только из показанных файлов, поэтому папки из одних скрытых файлов не появляются |
| `diff/MrDiffOpener.kt` | цепочка diff'ов: слева base-ревизия, справа локальный файл |
| `diff/MrDiffExtension.kt`, `diff/CommentMarkers.kt` | иконки тредов, **+**, диапазоны и suggestions в side-by-side, unified и односторонних diff |
| `core/MrReviewService.kt` | состояние проекта: репозитории и их подключения, загруженный MR/PR, checkout и возврат, отметки «просмотрен» |
| `util/MrBundle.kt`, `messages/MrBundle*.properties` | строки на английском и русском |
| `ui/*` | окно, форма подключения, карточка MR/PR, попапы тредов |

## Ограничения

- Треды, устаревшие после новых коммитов, не рисуются на полях; они есть на вкладке «Обсуждение» с пометкой «устарел».
- Для файлов, diff которых сервер не отдаёт из-за размера, комментарии к строкам недоступны.
- GitHub и Bitbucket принимают комментарии только к строкам hunk'ов diff; на остальных строках **+** не показывается.
- Suggestions: вставить можно в GitLab и GitHub, применить — только в GitLab (у GitHub и Bitbucket нет для этого API). Suggestions можно оставлять только на строки новой версии. Применённый suggestion — это новый коммит на сервере: обновите MR и сделайте checkout ещё раз, чтобы получить его локально.
- GitHub: автор approve не может его отозвать, только отклонить (dismiss) — для этого нужны права на запись в репозиторий.
- Bitbucket Data Center: resolve тредов и многострочные комментарии опираются на недокументированные поля API и могут не работать на старых серверах.
- Bitbucket Cloud: PR из форка выкачивается по https из форка; для приватного форка git нужны учётные данные к нему.
- Remote с SSH-алиасом хоста (`Host github-work` в `~/.ssh/config`) не сопоставляется с подключением.
- В side-by-side режиме диапазон ограничен одной стороной; чтобы выделить удалённые и добавленные строки вместе, переключите diff в unified.
- Если вы правили файлы на ветке `mr/<номер>` и затем выкачали другой MR/PR того же репозитория, эти правки уйдут в stash (с пометкой `mr-review` в `git stash list`), но «Вернуться» их не восстановит; изменения, спрятанные при первом checkout, восстановятся.

## Участие в разработке

Issues и pull request'ы приветствуются.

```bash
./gradlew test       # юнит-тесты логики, не зависящей от платформы
./gradlew runIde     # тестовая GoLand с плагином
```

С чего можно начать: черновики неотправленных комментариев, другие языки (добавьте `MrBundle_<язык>.properties`).
